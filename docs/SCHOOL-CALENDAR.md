# Ημερολόγιο σχολείου

Πρόσβαση από το μενού «Ημερολόγιο σχολείου». Προβολή μήνα για όλες τις καταχωρίσεις και «Προσεχώς / Εκκρεμότητες» για προγραμματισμένα γεγονότα, ανοιχτές εργασίες και εκπρόθεσμες εκκρεμότητες. Οι ολοκληρωμένες/ακυρωμένες εγγραφές παραμένουν στον μήνα, αλλά αφαιρούνται από τις υπενθυμίσεις. Η λίστα εκκρεμοτήτων αφορά όλο το επιλεγμένο έτος, ανεξάρτητα από τον μήνα.

Οι διαχειριστές (`admin`) διαχειρίζονται το ημερολόγιο και αναθέτουν τη δυνατότητα αυτή σε ενεργούς λογαριασμούς από «Δικαιώματα γραμματείας». Η ανάθεση αφορά μόνο το ημερολόγιο και ισχύει και για την ανάγνωση προηγούμενων ετών. Το `teacher_admin` δεν αποκτά πρόσθετη πρόσβαση ημερολογίου χωρίς ρητή ανάθεση. Μόνο το ενεργό σχολικό έτος επιδέχεται αλλαγές.

Κάθε εγγραφή έχει τίτλο, περιγραφή, ημερομηνίες, προαιρετικές ώρες, κατηγορία, κατάσταση και ορατότητα: μόνο γραμματεία (προεπιλογή), όλοι οι καθηγητές ή επιλεγμένοι καθηγητές. Οι εσωτερικές σημειώσεις παραμένουν πάντοτε ιδιωτικές στους διαχειριστές ημερολογίου. Οι καθηγητές έχουν μόνο ανάγνωση των επιτρεπόμενων εγγραφών. Δεν παρέχεται δημόσιος σύνδεσμος, αποστολή email, συνημμένα ή επανάληψη γεγονότων.

Η αρχική οθόνη εμφανίζει μέχρι πέντε επιτρεπόμενες καταχωρίσεις για τις επόμενες επτά ημέρες, μαζί με παλιότερες ανοιχτές εργασίες/εκκρεμότητες. Η διαγραφή είναι λογική: αφαιρεί την καταχώριση από όλες τις προβολές, διατηρώντας το ιστορικό. Οι ταυτόχρονες αλλαγές προστατεύονται με έκδοση εγγραφής. Καταγράφονται δημιουργία, αλλαγή, διαγραφή και ανάθεση/ανάκληση δικαιώματος.

## Ενεργοποίηση και αναβαθμίσεις

Νέα εγκατάσταση: οι τέσσερις πίνακες περιλαμβάνονται στο `schema.sql`.

Υπάρχουσα εγκατάσταση: `php bin/migrate_school_calendar.php`, με προρυθμισμένο ιδιωτικό λογαριασμό συντήρησης ή προσωρινά `CALENDAR_DB_USER` / `CALENDAR_DB_PASS` στο περιβάλλον. Απαιτούνται CREATE / REFERENCES και τα συνήθη SELECT / INSERT / UPDATE. Το migration είναι προσθετικό και επανεκτελέσιμο, δεν δημιουργεί γεγονότα/αναθέσεις και δεν αλλάζει δικαιώματα MySQL. Δεν εκτελείται DDL από web αίτημα. Δεν αποθηκεύονται διαπιστευτήρια στην τεκμηρίωση ή στις παραμέτρους εντολών.

Για μελλοντική υπογεγραμμένη αναβάθμιση, κάθε CREATE του `migrations/20261109_school_calendar.sql` πρέπει να γίνει ξεχωριστό SQL migration με `{{prefix}}` σε κάθε όνομα πίνακα (και FK). Στο υπογεγραμμένο manifest δηλώνονται υποχρεωτικά:

```json
"new_tables": ["calendar_managers", "school_calendar_events", "calendar_event_readers", "calendar_audit_log"]
```

Το AppPDO και η βάση αναγνωρισμένων πινάκων του νέου lifecycle περιλαμβάνουν και τους τέσσερις. Το `includes/lifecycle.php` είναι προστατευμένο αρχείο: η ενημέρωσή του διανέμεται χωριστά, με χειροκίνητη προετοιμασία, όπως στις προηγούμενες εκδόσεις. Δεν παρακάμπτουμε υπογραφές ή μητρώο ιδιοκτησίας. Ο παλιός lifecycle με υποστήριξη `new_tables` μπορεί να τους καταγράψει δυναμικά από το υπογεγραμμένο πακέτο. Δεν αλλάζουν ούτε αναδημοσιεύονται τα ήδη εκδομένα πακέτα 1.1.2.

Έλεγχοι: `php tests/test_school_calendar.php` και `php tests/test_school_calendar.php --mysql --user=root` σε τυχαία βάση δοκιμών (κωδικός μόνο μέσω `TEST_MYSQL_PASSWORD`). Δεν φορτώνονται ρυθμίσεις σχολείου ούτε μεταβάλλονται πραγματικές εγγραφές από τις δοκιμές.
