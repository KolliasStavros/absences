# Καταγραφή τεχνικών σφαλμάτων

Η ενότητα «Εργαλεία & Σύστημα → Τεχνικά σφάλματα» είναι μόνο για admin. Δεν καταγράφει προσπάθειες σύνδεσης, κωδικούς ή IP. Δεν απαιτεί νέους πίνακες βάσης.

## Ιδιωτική αποθήκευση

Χρησιμοποιείται APP_TECHNICAL_LOG_DIR από ιδιωτικό config ή environment. Ο φάκελος πρέπει να είναι εκτός app root και document root. Ο γονικός φάκελος πρέπει ήδη να υπάρχει και η PHP να μπορεί να δημιουργήσει/γράψει τον τελικό φάκελο. Οι ρυθμίσεις πρέπει να ισχύουν στο περιβάλλον του web server, όχι μόνο στο terminal.

Χωρίς ειδική ρύθμιση χρησιμοποιείται ο υποφάκελος technical-errors μέσα στο APP_MAINTENANCE_DIR, εφόσον έχει ρυθμιστεί ο ιδιωτικός χώρος συντήρησης. Δεν δημιουργούνται logs στον δημόσιο φάκελο. Η σελίδα admin εμφανίζει προειδοποίηση αν δεν είναι διαθέσιμη ιδιωτική αποθήκευση· το PHP error log λαμβάνει μόνο ασφαλή ένδειξη συμβάντος/αναγνωριστικό ως fallback.

## Τι καταγράφεται

- PHP warnings, notices και deprecations που δεν έχουν κατασταλεί με @, καθώς και διαθέσιμα fatal errors μετά τη φόρτωση του μηχανισμού.
- Μη χειριζόμενες εξαιρέσεις και εξαιρέσεις που περνούν από το υπάρχον safeError. Οι PDOException έχουν κατηγορία βάσης.
- Σφάλματα JavaScript runtime και unhandled promise rejection στις συνδεδεμένες σελίδες admin και στους δύο οδηγούς/οθόνες εκπαιδευτικού όπου περιλαμβάνεται ο reporter.

Κρατούνται μόνο αναγνωριστικό, χρόνος UTC, κατηγορία, τύπος, σχετική διαδρομή πηγής, γραμμή και σελίδα. Δεν κρατούνται αυτούσια μηνύματα, stack traces/arguments, SQL, query strings, σώματα αιτημάτων, ονόματα χρηστών, email, IP ή στοιχεία μαθητών. Έτσι μειώνεται η λεπτομέρεια διάγνωσης, αλλά δεν δημιουργείται αντίγραφο ευαίσθητων πληροφοριών.

Ο χρήστης λαμβάνει κωδικό αναφοράς όπου χρησιμοποιείται safeError. Οι PHP προειδοποιήσεις καταγράφονται χωρίς να εμφανίζεται το τεχνικό μήνυμα στον browser. Τα browser reports δεν αλλάζουν την εμφάνιση ή τις καταχωρήσεις της εφαρμογής.

## Όρια και φίλτρα

Αρχεία JSONL ανά ημέρα UTC, έως περίπου 1 MiB ημερησίως και έως 30 συμβάντα ανά PHP αίτημα. Η διατήρηση είναι 30 ημερολογιακές ημέρες UTC: η εκκαθάριση παλιών διαχειριζόμενων αρχείων γίνεται στην επόμενη πρόσβαση στον μηχανισμό, όχι από ανεξάρτητο scheduler. Άσχετα αρχεία δεν διαγράφονται.

Ο browser στέλνει έως 10 διαφορετικές αναφορές ανά φόρτωση σελίδας. Το endpoint απαιτεί ενεργή σύνδεση και CSRF και δέχεται έως 20 αναφορές ανά συνεδρία/λεπτό και μικρό, ελεγχόμενο JSON. Δεν εκτίθεται ως ανώνυμος γενικός δέκτης logs.

Η οθόνη φιλτράρει ημέρα αρχείου UTC, κατηγορία και ακριβή κωδικό αναφοράς. Οι ώρες εμφανίζονται σε Europe/Athens. Οι επαναλήψεις ομαδοποιούνται ανά τύπο, αρχείο, γραμμή και σελίδα και εμφανίζονται έως 200 ομάδες. Όταν αναζητείται ένας συγκεκριμένος κωδικός, το πλήθος αφορά μόνο αυτόν τον κωδικό.

## Περιορισμοί

Σφάλματα πριν από το bootstrap, αδυναμία εκκίνησης PHP, πλήρης εξάντληση πόρων και σφάλματα Apache/PHP-FPM μπορεί να εμφανίζονται μόνο στα logs του server. Τα logs της πλατφόρμας παραμένουν χωριστά και χρειάζονται τη δική τους προστασία και πολιτική διατήρησης. Εξαιρέσεις που καταπίνονται χωρίς safeError ή χειρισμένα αποτυχημένα αιτήματα δεν καταγράφονται αυτόματα. Λανθασμένοι υπολογισμοί χωρίς τεχνική εξαίρεση χρειάζονται λειτουργικές δοκιμές.

Οι browser αναφορές είναι ενδεικτικά στοιχεία διάγνωσης, όχι αποδεικτικά ταυτότητας ή ενέργειας χρήστη. Οι παλιές καταγραφές μένουν εκτός backup εφαρμογής, στον ιδιωτικό χώρο. Το τρέχον bootstrap ασφαλείας και ο μηχανισμός καταγραφής προστατεύονται από αντικατάσταση κατά restore παλιότερου backup.
